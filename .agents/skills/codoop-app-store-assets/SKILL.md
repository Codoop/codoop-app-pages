## Art direction from the project

Inspect the user's project before choosing a visual direction: look for brand guidelines, logo and icon assets, design tokens, typography, color definitions, existing app screens and relevant marketing pages. Use the supplied real screenshots and explicit preferences as primary evidence; distinguish an existing brand convention from an incidental UI color. Note which evidence informs the palette, type, composition and tone in the review. If sources conflict, follow the user's explicit direction; if important visual decisions remain unsupported, propose a direction and label it as a suggestion rather than inventing a brand rule.

Develop a visual direction appropriate to the product, audience and screenshots. Choose backgrounds, typography, image treatment, decoration and composition independently for this project; they need not resemble the example. Design the composition of each placement around its message, screenshot, orientation and reading order. Consider different arrangements, scale, alignment, whitespace, image counts, crops and treatments when they serve the content. Maintain cohesion across the set without forcing identical compositions or arbitrary variation. Do not claim a style is mandated by Apple. Respect explicit preferences throughout.

Before design and again before export, check Apple's current [screenshot specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications/) and [creative asset specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/creative-assets-specifications/). Record date and sources, and select sizes and formats for the supported devices, orientations, regions and placements. Do not assume source image dimensions are upload specifications. If current requirements cannot be verified, say so and do not claim upload readiness. Ask for real screenshots for required devices that cannot be represented faithfully. Preserve aspect ratios; never fabricate UI.

Consult `assets/review.html` as one illustrative case and copy it into the user's project as a starting point for the review. Copy its companion stylesheet `assets/iphone-frame.css` beside it. Adapt the example palette, typography, copy, dimensions and layout to the project. Create the actual canvas markup and CSS around the project's own visual direction and each placement's content; freely replace the example's layout and rendering code. Retain or rebuild the review interactions and use the same canvases for export. Use local assets and preserve originals. By default prepare one portrait design per supplied screenshot and two distinct landscape designs for Header and Search Results. Combine related screenshots when useful and disclose resulting count changes or missing device screenshots. Check the current per-device screenshot limit and discuss selection if exceeded. Use the current official placement specifications and templates, not example dimensions, including safe areas and device-specific cropping. Keep marketing recommendations distinct from Apple requirements.

## iPhone frames and landscape composition

Place visible iPhone screenshots in the reusable `.iphone > .iphone-screen > img` frame from `assets/iphone-frame.css` in portrait and landscape artwork. Open `assets/iphone-frame.html` alongside the stylesheet to preview the frame in isolation, load a local screenshot and check the optional cutout. The default frame approximates the [iPhone 16 Pro](https://support.apple.com/en-us/121031). When a different model is known, match its body and display proportions and camera cutout using a device-specific product photo and display specifications. Compare the bezel, corner shape, side controls and cutout against that photo before review. Preserve screenshot aspect ratio and original UI. Use the supplied Dynamic Island modifier only when the screenshot lacks the cutout and the overlay clears actual UI. For an explicitly requested frameless treatment or a placement that requires a raw screenshot, follow that requirement.

Compose Header and Search Results independently. Start with a primary phone or framed screen whose visible portion occupies at least 80% of the canvas height. Scale up the main screen and headline before adding visual decoration. Let the phone extend beyond a canvas edge when that makes the relevant UI larger, keeping the feature and headline inside the placement's safe area. Each landscape design can use one to three of the user’s supplied screenshots. Honor the user’s choice of count and screenshots when specified. Otherwise, inspect the supplied screens and choose the count and grouping independently for Header and Search Results. Use one screenshot for a single focal feature, two for complementary views or consecutive steps, and three when each adds a distinct part of the same story. Keep one screen dominant and arrange supporting screens in reading order. Check that the featured UI remains legible and explain the selection briefly in the review.

Before review, inspect both landscape canvases at the target placement preview size. If unavailable, use a 320 CSS-pixel-wide preview. Verify the headline is readable, the featured interaction is recognizable, and the phone and copy occupy the canvas without a large unintentional gap. If the layout feels sparse, increase the size of the primary screen or typography, tighten the gap, and recheck the crop. Treat the 80% and 320px figures as internal review heuristics.

Provide a locally openable HTML review with overview, individual selection, zoom and a control-free full-size view of the same canvases used for export. Use real screenshots as the main subject, readable concise copy and consistent visual hierarchy. Device frames or crops must accurately reflect the product. Check every design in a browser for layout, loaded images, cropping, contrast and consistency; if unavailable, explicitly state what was not visually verified. Revise in response to feedback.

**Wait for explicit design approval before exporting final images.** Approval of design does not authorize upload or publication. After approval, export each exact canvas at native dimensions and 1× as PNG using available tools. Verify every image's dimensions, color mode, lack of alpha, file loading and visual appearance, and check applicable safe areas. App Store Connect device crop previews require access to that interface; report if unverified. Place output in a clear export directory and report filenames, sizes, purposes and checks. Never upload or submit unless explicitly requested.
